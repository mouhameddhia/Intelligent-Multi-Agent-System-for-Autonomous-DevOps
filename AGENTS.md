# Repository guidance

For every meaningful feature change, integration, bug fix, or evaluation, update [`EVALUATION_LOG.md`](EVALUATION_LOG.md) in the same work session. Add a dated entry, record the baseline and changed behavior where comparable, include sample size and concrete results/evidence, and state limitations. Mark missing measurements as “not measured”; never invent a baseline or imply a small benchmark proves production-wide performance. Keep the current scorecard and evaluation gaps in sync with new evidence.
